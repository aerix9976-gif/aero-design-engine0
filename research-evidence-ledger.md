# Research Evidence Ledger

## Use this skill when

Cross-source research, design-system decisions, package/version decisions, and recommendations that may be stale.

## Prerequisites
- A concrete question and candidate sources.

## Workflow
1. Split opinion, design inspiration and technical facts into separate claim types.
2. Use primary docs for APIs, official product docs for product capabilities, Context7 for versioned library evidence, and TubeAlfred for tutorial context.
3. Record the publication/update date when recency matters and prefer evidence matching the requested timeframe.
4. Keep contradictory evidence visible and state which source is authoritative for which claim.
5. Attach confidence and an explicit follow-up test for unresolved questions.

## Hard rules
- Don't cite a video for API truth when current docs are available.
- Don't hide uncertainty or infer a missing version.
- Don't turn a popularity signal into proof.

## Acceptance criteria
- [ ] Each material claim can be traced to evidence.
- [ ] Freshness and version are preserved.
- [ ] Uncertainty and unresolved conflicts are visible.

## Source basis
- Context7 official research documentation
- TubeAlfred source discovery
